## V1과 후속 구현

V1은 PR #13 병합본을 유지한다. API 7.1의 보완 1~9와 작업별 자동 예약 허용은
[BE-22](https://app.notion.com/p/40324a392ba9815a9b8ef27466cb39b1),
[GitHub #16](https://github.com/kau-sanhak-10/backend/issues/16)에서 추적한다.
기존 데이터·토큰을 확인하고 이관·무효화 순서를 정한 뒤 후속 마이그레이션을 적용한다.
인증 스키마를 우선 협의하고 실제 서비스 동작 테스트는 각 작업에서 수행한다.

## AI 경계

실험 추출 결과의 `needs_review`만으로 예약을 막거나 사람에게 이관하지 않는다.
참고정보만 미확인이면 값만 표시하며 확인 업무·알림·OWNER_CHECK를 생성하지 않는다.
필수정보 미해결·안전·직접 상담 요청은 기존 이관 기준을 따른다.
작업별 필수정보·안전·서비스 범위·최신 입력 버전을 서버에서 검증한다.
지연된 AI 응답은 사장님 수정값을 덮어쓰지 못한다. 주소 변경은 제안·고객 수락 후에만 반영한다.

AI는 다음 행동만 반환한다. 프론트가 Spring의 가능시간을 조회하고 고객 선택·확인 후
예약 API를 호출한다. Spring이 권한·인증·최신 일정·중복을 최종 검증해 저장한다.
LangGraph가 예약 API를 직접 호출하지 않는다.

Spring 클라이언트·작업 상태·결과 적용은 정채우(BE-05/08), FastAPI·LangGraph·공통 응답은
원민재(DS-05/AI-02~06), 내부 접속·권한·배포는 박준형(IF-04~06/10)이 맡는다.
재시도는 Spring 한 곳에서 관리한다. FastAPI/SDK 자동 재시도는 끄고 최초 포함 최대 2회,
시도당 30초·전체 대기 예산 60초로 제한한다. 권한·크레딧·일일 할당량 오류는 자동 재시도하지 않는다.
재시도·결과 적용 전 입력 버전·응대 주체를 다시 확인한다.

모델 호출 기반은 Bedrock이다. 멀티모달 모델과 별도 YOLO+OCR+룰 실행 경로를 같은 출력·평가
기준으로 비교·개선한다. 둘의 실험 완료를 기본 연동의 선행 조건으로 두지 않는다.
모델·리전·권한·비용은 IF-10/AI-03에서 실제 호출로 확인한다. 기존 직접 API 실험은 과거 비교 근거다.
